# To-Do Application — Phase 1: WinForms / MVP

Учебное приложение для управления списком задач, реализованное на C# / .NET 8 с использованием Windows Forms и паттерна Model–View–Presenter (MVP).

## Цель проекта

Изучить построение многослойного приложения, разделение пользовательского интерфейса и логики представления, взаимодействие через события и интерфейсы, а также Dependency Inversion Principle (DIP).

## Функциональность

- Создание задач.
- Просмотр списка задач.
- Отметка задач как выполненных.
- Удаление отдельных задач.
- Удаление всех выполненных задач.
- Перемещение задач вверх и вниз по списку.

Данные хранятся в памяти приложения (`InMemoryTodoRepository`) и не сохраняются между запусками.

## Архитектура

| Проект | Ответственность |
|---|---|
| ToDoApplication.Domain | Сущность `TodoItem`, доменные правила и исключения |
| ToDoApplication.Application | Use Cases и интерфейс `ITodoRepository` |
| ToDoApplication.Infrastructure | Реализация `InMemoryTodoRepository` |
| ToDoApplication.Presentation | `TodoPresenter`, `ITodoView`, `TodoItemDto` |
| ToDoApplication.WinForms | Реализация пользовательского интерфейса |
| ToDoApplication.CompositionRoot | Создание и связывание компонентов |
| ToDoApplication.Tests | Модульные тесты |

### MVP — Passive View

Пользовательские действия обрабатываются формой, которая порождает собственные события, определённые интерфейсом `ITodoView`.

`TodoPresenter` подписывается на эти события, вызывает соответствующие Use Cases, получает актуальные данные и передаёт их View через методы интерфейса.

Пример потока выполнения:

```text
Button.Click
    ↓
Form1
    ↓ AddButtonClicked
TodoPresenter
    ↓
CreateTodoItemUseCase
    ↓
ITodoRepository
    ↓
InMemoryTodoRepository
```

После операции Presenter получает актуальный список задач и вызывает `ITodoView.DisplayTodoItems()`.

`Form1` не зависит от `TodoPresenter` и не вызывает Use Cases напрямую.

`TodoPresenter` зависит от `ITodoView`, а не от конкретной реализации `Form1`. Интерфейс находится в Presentation, что позволяет избежать зависимости Presentation от WinForms.

## Запуск и тестирование

Требуется Windows и .NET 8 SDK.

Для проверки сборки:

```bash
dotnet build
```

Для запуска тестов:

```bash
dotnet test
```

Для запуска приложения можно использовать стартовый проект `ToDoApplication.CompositionRoot` в Visual Studio.

## Выводы

MVP позволяет отделить управление пользовательскими сценариями от конкретных визуальных компонентов.

Преимущества:

- Логика представления отделена от WinForms.
- Presenter можно тестировать с подставной реализацией `ITodoView`.
- View не зависит от конкретного Presenter.
- Зависимости между проектами организованы через абстракции.

Недостатки и компромиссы:

- Требуется дополнительный интерфейс и класс Presenter.
- Необходимо вручную подписываться на события.
- Presenter явно управляет обновлением View.
- Для очень маленького приложения дополнительные абстракции могут оказаться избыточными.

**MVP не является плохим паттерном.** Его полезность зависит от сложности интерфейса, требований к тестированию и выбранного UI-фреймворка.
